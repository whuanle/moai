# 知识库文档异步向量化与通用任务表设计

## 目标

知识库文档向量化通过 MQ 异步执行，并使用统一的后台任务表记录任务生命周期。向量化模块只处理已经保存的原文切片和元数据，不负责生成元数据。

功能保留两个独立选项：

- 对原文切片向量化。
- 对已有元数据向量化。

两个选项允许任意一个单独启用，也允许同时启用，但不能同时关闭。

## 通用任务表

新增 `worker_task` 表，作为各业务模块共用的后台任务表，不建立 Wiki 专用任务表。

字段沿用旧版设计：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `uuid` | 任务主键，由应用生成 UUID |
| `bind_type` | `varchar(20)` | 关联类型；文档向量化使用 `embedding` |
| `bind_id` | `integer` | 关联对象 ID；文档向量化使用文档 ID |
| `state` | `integer` | 任务状态 |
| `message` | `text` | 状态说明或错误信息 |
| `data` | `text` | 任务自定义 JSON 数据 |
| `create_user_id` | `bigint` | 创建人 |
| `create_time` | `timestamp with time zone` | 创建时间 |
| `update_user_id` | `bigint` | 最后修改人 |
| `update_time` | `timestamp with time zone` | 更新时间 |
| `is_deleted` | `bigint` | 软删除标记 |

主键使用 UUID。表名、字段名、审计字段默认值和 PostgreSQL 映射遵循现版数据库项目约定，由 EF Core 实体与配置管理。

`state` 使用现有通用 `WorkerState`：

- `Wait`：任务已创建，等待消费。
- `Processing`：消费者已开始处理。
- `Successful`：任务完成。
- `Failed`：任务失败，`message` 保存可展示的失败原因。
- 其他已有终态保持通用枚举定义，不为 Wiki 新建状态枚举。

## 任务数据

向量化任务的 `data` 保存 JSON：

```json
{
  "wikiId": 1,
  "documentId": 5,
  "isEmbedSourceText": true,
  "isEmbedMetadata": true
}
```

不保存元数据生成模型 ID、渠道 ID或元数据生成策略。模型渠道由知识库配置的向量模型解析；元数据生成已属于独立模块。

## 接口与消息

触发向量化接口保留：

```text
POST /api/wiki/{wikiId}/documents/{documentId}/embedding
```

请求体只包含：

- `isEmbedSourceText`
- `isEmbedMetadata`

处理器执行以下校验：

1. Wiki、文档、团队成员权限有效。
2. Wiki 已配置可用的向量模型及维度。
3. 至少启用一个向量化选项。
4. 启用原文向量化时，文档存在切片。
5. 启用元数据向量化时，文档存在已生成元数据。
6. 不存在相同 `bind_type`、`bind_id` 且状态为 `Wait` 或 `Processing` 的活动任务。

校验通过后，在同一业务操作中创建 `worker_task`，再发布 MQ 消息。消息只携带 `TaskId`，消费者以任务记录作为配置真源，避免消息字段与数据库配置漂移。

接口返回任务 ID，使前端可以立即跟踪状态。

## 消费流程

消费者收到 `TaskId` 后：

1. 查询未删除的任务；任务不存在或已进入终态时直接确认消息。
2. 原子地将任务从 `Wait` 更新为 `Processing`，防止重复消费并发执行。
3. 解析 `data`，读取 Wiki、文档、切片及已保存元数据。
4. 清理该文档旧的向量记录。
5. 按两个选项构建待向量化记录。
6. 调用 Wiki 配置的向量模型生成并写入向量。
7. 成功后设置文档 `IsEmbedding = true`、Wiki `IsLock = true`，任务更新为 `Successful`。
8. 消费失败或进入死信时，将任务更新为 `Failed` 并记录错误信息。

重新向量化开始时不提前清除 `IsEmbedding`。旧向量仅在消费者实际开始重建时处理；任务失败时保留明确失败状态，避免将“旧版本已向量化”和“本次任务失败”混为一个布尔值。

## 查询与前端

文档向量化详情响应增加当前或最近任务信息：

- `taskId`
- `taskState`
- `taskMessage`

查询优先返回该文档最新的活动任务；没有活动任务时返回最近一条终态任务。

前端向量化区域：

- 删除“元数据生成模型”选择器。
- 保留“向量化原文切片”和“向量化已有元数据”两个复选框。
- 两项均未选择时阻止提交并显示校验提示。
- 任务为 `Wait` 或 `Processing` 时禁用提交按钮，展示等待或处理中状态，并定时刷新详情。
- 任务进入 `Successful` 或 `Failed` 后停止轮询；成功刷新向量数量，失败展示任务消息。
- 页面重新打开时依据后端任务状态恢复轮询，不依赖浏览器本地状态。

独立的元数据生成区域和接口不在本次变更中删除或重构。

## 并发与一致性

应用层在创建任务前检查活动任务。数据库为 `bind_type`、`bind_id`、`state` 建立查询索引；若 PostgreSQL 迁移约定允许，增加仅覆盖活动状态的唯一索引，作为并发提交的最终保护。

创建任务成功但 MQ 发布失败时，处理器将任务更新为 `Failed` 并记录发布错误后返回失败。消费者使用状态条件更新获取执行权，重复投递不会重复执行同一任务。

## 测试

后端覆盖：

- 两个选项的三种有效组合与全部关闭校验。
- 仅元数据模式下无元数据时拒绝创建任务。
- 重复活动任务返回冲突。
- 创建任务后发布仅含 `TaskId` 的消息。
- 消费者状态流转、成功结果、重复消息和失败状态。
- 向量化流程不调用元数据生成服务。

前端覆盖：

- 页面不再展示元数据模型选择器。
- 两个复选框分别提交正确参数。
- 两项均未选择时不调用接口。
- 等待/处理中状态禁用按钮并轮询。
- 成功或失败后停止轮询并展示结果。

## 非目标

- 不在向量化流程中生成、覆盖或追加元数据。
- 不为每个业务模块建立独立任务表。
- 本次不提供任务中心、任务历史列表或手动取消功能。
- 本次不修改独立元数据生成模块的交互和策略。
