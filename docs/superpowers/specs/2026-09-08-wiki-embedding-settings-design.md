# 知识库向量化设置设计

- 日期：2026-09-08
- 状态：待评审
- 关联：[知识库 SDD](../../wiki/sdd.md) ｜ [知识库 BDD](../../wiki/bdd.md) ｜ [知识库 TDD](../../wiki/tdd.md) ｜ [前端规范](../../../ui/docs/frontend-conventions.md)

## 目标

在团队知识库详情的“设置”页提供可管理的向量化配置，使团队 Owner/Admin 能选择已授权的向量模型与元数据模型，设置向量维度和切片参数。首次文档向量化后，该配置保持可见但锁定，防止新旧文档使用不兼容的向量数据。

## 范围

- 复用现有 `GET /wiki/model-options?teamId=` 和 `PUT /wiki/{id}/embedding-config` 接口。
- 在 `WikiDetail` 的管理员设置表单增加独立的“向量化配置”分区。
- 维度使用可搜索、可手填的组合框，预设 `256`、`512`、`1024`、`2048`、`2560`、`4096`。
- 输入值必须为 $1$ 至 $4096$ 的整数；保留旧配置的非预设值回显。
- 基础信息与向量化配置使用独立保存动作，避免任一组失败影响另一组。

不包含：新建知识库时配置默认模型、系统级默认配置、改配置后的历史文档重新向量化。

## 组件与数据流

1. 页面加载时获取知识库详情；管理员同时请求当前团队可用模型选项。
2. 向量模型下拉渲染 `embeddingModels`，元数据模型下拉渲染 `conversationModels`；后端已保证候选模型启用且为公开或团队授权。
3. “保存向量化配置”仅提交模型 ID、维度、切片长度和重叠，成功后刷新详情并提示成功。
4. `isLock=true` 时禁用向量化分区和保存按钮，显示配置锁定原因；名称、简介、公开设置和头像继续可编辑。
5. Member 与公开知识库的非成员维持当前只读设置视图，且不请求模型选项。

## 契约与校验

前端复用 `ui/src/api/wiki.ts` 中已有的经认证 API 封装；不手改 Kiota 生成代码。详情类型补齐 `embeddingModelId`、`embeddingDimensions`、`metadataModelId`、`chunkSize`、`chunkOverlap`、`isLock`，用于表单回显。

前端在提交前校验模型已选择、维度为范围内整数、切片长度为 $1$ 至 $8192$、重叠不小于 $0$。服务端保留同等或更严格的权威校验：模型类型、团队授权、角色权限以及锁定状态。

## 失败处理

- 模型候选项加载失败时保留基础设置可用，向量化分区显示加载失败反馈且不可提交。
- 配置保存失败时不清空表单，以便管理员修改后重试。
- 后端返回锁定冲突时刷新详情，展示最新锁定状态。

## 验证

- 前端单测覆盖：管理员加载并保存配置、模型候选按类型显示、预设和手填维度校验、锁定禁用、非管理员不请求选项。
- `npm run typecheck`、`npm run lint`、`npm run test` 验证前端改动。
- 增补知识库 BDD/TDD，记录配置编辑与锁定场景的验证映射。

## 决策

- D1：维度不是模型能力元数据，而是管理员可填的项目配置；预设仅降低常规操作成本。
- D2：首个向量化完成后不可改配置；不引入历史文档重处理任务。
- D3：仅复用当前团队模型授权边界，不新增知识库私有模型授权。
