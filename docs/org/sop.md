# 角色组织（Org，ORG）运维手册（SOP）

> 关联：[SDD](./sdd.md) ｜ [BDD](./bdd.md) ｜ [TDD](./tdd.md) ｜ [SOP](./sop.md)
> 面向：平台管理员（admin/root）。验收流程见第 3 节。

## 1. 存量库升级（一次性）

**新库无需任何操作**（EnsureCreated 全新建库）。存量库**默认也无需手工操作**——服务启动时幂等 DDL 自动补 `org_role`/`org_user_role` 两表（见 [SDD 数据模型](./sdd.md)）；手工路径（与启动 DDL 等价，DBA 可选）：

```bash
docker exec -i moai-postgres psql -U postgres -d moai < asserts/org.sql
```

不升级的典型症状：组织角色接口 500 `42P01: relation "org_role" does not exist`。

## 2. 管理页操作（「组织角色」菜单）

入口：侧边栏 **管理 → 组织角色**（原「团队管理」入口，路由不变），页内两个 Tab：

- **团队管理 Tab**：原团队管理（转让负责人/启停用），行为不变。
- **角色管理 Tab**（左侧组织树 + 右侧成员列表）：
  - **新建组织**：无全局新建按钮——树顶「默认根」右侧 + 新建**顶级组织**（无上级），每个组织节点右侧 + 在其下新建**下级组织**；表单仅填名称（≤50，同一上级下不可重名）；
  - **调整层级**：直接**拖拽**组织节点——拖入某组织内=成为其下级，拖到节点之间=同级换挂，拖到「默认根」=升为顶级；拖到自身或其下级会被拦截（防环）；
  - **编辑**：改名（仅名称，层级不走编辑）；
  - **设为默认角色 / 取消默认**（右栏头部星标）：设置后**新注册用户自动获得该角色**（含 OAuth 自动建号），全局唯一、后设覆盖；取消需二次确认，存量绑定不变；
  - **成员管理**：左树选中组织后右栏即其成员列表（按用户管理页样式展示头像/用户名/昵称/邮箱/手机号/角色/状态/加入时间）——搜索成员、添加成员（搜索全站用户）、移除成员（整体覆盖该用户组织集合）；
  - **按用户分配**（左树工具栏）：选用户 → 多选其组织集合 → 保存为整体覆盖（清空选择=移除其全部组织角色）；
  - **删除**：需二次确认；存在下级组织时会被拒绝（先调整或删除下级），其下绑定用户自动解绑，默认角色被删时默认设置自动清空。

## 3. 验收流程

1. `node local-dev/org-e2e.mjs`（后端运行中）应 38/38 PASS；
2. 管理员走查 [@ORG-S34](./bdd.md#org-s34)：菜单文案为「组织角色」，默认团队 Tab，切角色 Tab 在默认根/节点 + 建两级组织、拖拽换挂层级、选中看右栏成员、设默认后注册新用户验证自动获得；
3. 普通用户登录确认看不到「管理」区块（或访问 /admin/teams 被重定向）。

## 4. 排障表

| 症状 | 原因 | 处置 |
|---|---|---|
| 角色接口 500 `relation "org_role" does not exist` | 存量库未升级且启动 DDL 被跳过 | 第 1 节执行 asserts/org.sql |
| 调整上级报 400「不能将角色移动到自身或其下级角色之下」 | 目标上级在被移动角色的子树内（含自身） | 选子树外的上级；SOP 不提供绕过（防环硬约束） |
| 创建报 409「同一上级下已存在同名角色」 | 同父重名 | 改名或挂到其他上级下 |
| 删除报 400「存在子角色」 | 非叶子角色 | 先删除/迁移其子角色 |
| 列表顺序"错乱" | 不会发生：列表按物化路径**数值**层级序 | 如遇同级乱序请提 bug（附 path 截图） |
| 新注册用户没拿到默认角色 | 默认角色被清空/被删，或注册时钩子静默跳过（角色缺失） | 检查角色树默认徽标仍在；重新设置默认即可，存量用户不追溯 |
| 普通用户 403 | 门禁为 IsAdmin 口径（设计如此） | 由管理员维护；root 亦具备权限 |
