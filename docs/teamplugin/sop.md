# 团队插件模块操作手册（SOP）

> 关联：[SDD](./sdd.md) ｜ [BDD](./bdd.md) ｜ [TDD](./tdd.md) ｜ [SOP](./sop.md)

## 1. 概念

| 类型 | 归属 | 谁能用 |
|---|---|---|
| 系统插件-公开 | 系统（`is_system=true`, `is_public=true`） | 所有团队 |
| 系统插件-私有 | 系统（`is_system=true`, `is_public=false`） | 仅被授权团队（管理员在 `/plugin` 授权） |
| 团队插件 | 某团队（`is_system=false`, `team_id=teamId`） | 仅该团队成员；Owner/Admin 管理 |

## 2. 日常操作

### 管理员：系统插件私有授权
- 入口：`/plugin` → 自定义/动态 Tab。私有插件行内的小图标「授权团队」。
- 打开抽屉 → 选择团队 → 添加；列表可移除已授权团队。
- 公开插件无需授权（抽屉显示提示）。

### 团队 Owner/Admin：团队插件
- 入口：团队详情页 → 「插件」区块，分为「自定义插件」「动态插件」两个 Tab。
- 自定义 Tab：「导入 MCP / 导入 OpenAPI」创建；行内可查看函数、刷新 MCP（MCP 且团队自有）、编辑、删除（团队自有时）。
- 动态 Tab：「新建实例」创建动态插件实例；行内可运行、编辑、删除（团队自有时）。模板下拉来自后端注册表已发现的动态插件。
- 分类筛选与编辑仅管理员可见（分类列表接口仅管理员可读）；成员按列表返回的分类名查看。
- **团队变量插值**：MCP/OpenAPI 自定义插件的 Header/Query 值可写 `{变量名}`（如 `Bearer {token}`），运行时按插件所属团队变量替换（私密变量解密注入）；数据库始终保存占位符原文。变量先在「变量」页建好，再导插件即可通过连接校验；占位符对应的变量不存在时 MCP 导入/刷新会失败（409）。

### 团队 Member
- 只读 + 运行：可筛选、查看函数、运行团队可用插件（团队自有或公开/已授权系统插件）；无创建/编辑/删除/刷新入口。

## 3. 常见问题

| 现象 | 处理 |
|---|---|
| 系统插件抽屉提示「公开插件无需授权」 | 该插件为公开，所有团队已可用 |
| 团队插件列表看不到某私有系统插件 | 需管理员在 `/plugin` 为该团队授权 |
| 团队创建插件返回 403 | 当前用户非 Owner/Admin，或不在团队中 |
| 创建动态实例返回 409 | 实例 key 已被其它团队使用，或与系统插件 key 冲突 |
| 同团队用已有实例 key 保存 | 视为更新该实例（实例 key 不可变） |
| 团队插件编辑/删除报 404 | 该插件可能已被删除，或不属于当前团队 |
| 刷新 MCP 报 403 | 仅团队 Owner/Admin 可刷新，且需团队自有 MCP 插件 |
| 成员查看不了分类筛选 | 分类列表接口仅管理员可读，成员按分类名展示 |
| 导入/刷新 MCP 报 409 且配置无误 | Header/Query 引用的 `{变量名}` 在该团队不存在或已删除，检查变量管理页 |

## 4. 验收流程

1. 执行 `asserts/plugin_team_authorization.sql`（已有库需建表）。
2. `TP_BASE=http://127.0.0.1:<port> node local-dev/team-plugin-e2e.mjs` → 19/19 PASS。
3. 前端三件套绿（vitest + tsc + eslint）。
4. 浏览器：
   - admin 登录 → `/plugin` → 私有自定义插件授权团队。
   - 团队 Owner 进入团队详情 → 「插件」→ 自定义/动态两 Tab，导入 MCP/OpenAPI、新建动态实例、运行、删除。
   - Member 登录 → 团队详情 →「插件」只读 + 运行/查看函数。
