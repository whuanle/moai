# 团队定时器 BDD

> 前端菜单自 2026-10-30 起展示为「自动化」（菜单 key/路由 section 仍为 `timers`），实体文案称「自动化任务」。

```gherkin
Feature: 团队定时器管理
  团队管理员把已发布的 Agent/流程应用绑定到定时器，按 cron 定时无头执行固定提问，并可立即执行调试。

  @TIMER-S1
  Scenario: 创建定时器并注册调度
    Given 团队里有一个已发布的 Agent 应用
    When 管理员创建定时器：名称、绑定应用、5 段 cron（UTC）、执行内容、重试策略并启用
    Then 创建成功返回定时器 id
    And 列表中能看到该定时器的绑定应用名称与下次调度时间
    And 同名再建返回冲突
    And 非法 cron（段数/取值范围不合法）被拒绝且不落库

  @TIMER-S2
  Scenario: 绑定应用合法性
    When 管理员创建定时器绑定一个未发布的应用
    Then 请求被拒绝并提示先发布应用

  @TIMER-S3
  Scenario: 角色门禁
    When 团队成员（Member）创建定时器
    Then 被拒绝（仅管理员可管理定时器）
    But 该成员可以查看定时器列表

  @TIMER-S4
  Scenario: 立即执行成功并记录历史
    Given 定时器绑定的应用可正常回答
    When 管理员点击立即执行
    Then 返回执行记录 id 并异步执行
    And 执行历史出现一条手动触发记录：状态成功、尝试 1 次、触发人为操作人、回答文本完整
    And 定时器的最近触发时间被刷新

  @TIMER-S5
  Scenario: 失败按重试策略重试后终态失败
    Given 定时器执行内容会使应用执行失败，重试次数 1、间隔 10 秒
    When 管理员立即执行
    Then 执行记录先进入待重试（含下次重试时间）
    And 重试仍失败后终态为失败、尝试 2 次、失败原因完整

  @TIMER-S6
  Scenario: 停用与删除的调度语义
    When 管理员停用定时器
    Then 列表不再返回下次调度时间
    When 管理员删除定时器
    Then 列表不再出现该定时器
    But 执行历史仍可查看（保留 2 条）
```

```gherkin
Feature: 定时器页面（团队分区）
  团队管理分区下的定时器列表页，管理员可建/改/删/启停/立即执行/看历史。

  @TIMER-S7
  Scenario: 管理员视角的列表与操作
    Given 当前用户是团队管理员
    Then 可见新建按钮与每行的立即执行/历史/编辑/删除操作与启用开关
    And 执行指令列约束宽度省略号截断（悬停显示全文），超宽 URL 不撑爆表格；列总宽超出时表格横向滚动、操作列固定右侧

  @TIMER-S8
  Scenario: 成员视角只读
    Given 当前用户是团队成员
    Then 无新建按钮与操作列，仅能查看列表

  @TIMER-S9
  Scenario: 新建弹窗与执行历史抽屉
    When 管理员打开新建弹窗
    Then 可见绑定应用（仅列出已发布应用，未发布的不出现在下拉；无已发布应用时显示空态提示）/调度表达式选择器/执行指令/重试配置
    When 点击立即执行
    Then 执行历史抽屉打开并默认加载最近 10 条，执行中有记录时自动轮询到终态

  @TIMER-S10
  Scenario: 调度表达式选择器（design-system CronExpressionInput）
    Given 新建/编辑弹窗使用统一调度表达式组件（常用/自定义双模式，展示时区北京时间 UTC+8，提交值 UTC）
    When 管理员在常用模式选择「每天 09:00」
    Then 表达式生成为「0 1 * * *」且预览显示「每天 09:00 执行」与按北京时间的下次执行时刻
    When 管理员选择每周/每月模式
    Then 周几/日期随北京时间向西借位联动换算（如周一 3 点 = 周日 19 点 UTC），每月 1 日叠加借位跨月界不可表达时该日期禁用
    When 管理员切换到自定义按字段编辑
    Then 支持 , - / 与 * 组合并实时校验，非法时提示且外发空串由必填校验兜底
    When 打开已有定时器编辑
    Then 表达式反解回常用模式回显（非常用形态直接落在自定义 tab）

  @TIMER-S11
  Scenario: 不开启重试时无需填写重试间隔
    Given 失败重试为 0（不开启重试），重试间隔输入框不渲染
    When 管理员直接保存
    Then 提交体重试间隔兜底为默认 60 秒（后端字段必填 10-3600），不报「重试间隔仅允许 10-3600 秒」
```

```gherkin
Feature: 列表执行状态展示
  列表新增「执行状态」列（原启用开关列更名「启用」），展示每个定时器最近一次执行的实时状态。

  @TIMER-S12
  Scenario: 执行状态列与活跃轮询
    Given 列表响应携带 lastExecutionStatus（最近一次执行状态，未执行过为 null；等待/执行中/待重试为活跃态）
    When 某定时器存在正在执行的任务
    Then 该行执行状态列显示活跃态呼吸灯（执行中/等待中/重试中）
    And 页面每 5 秒自动刷新列表，状态翻到终态（成功/失败）后停止轮询
    When 最近一次执行已结束
    Then 显示终态结果（成功绿点/失败红点），未执行过的定时器显示 -

  @TIMER-S13
  Scenario: 执行超时与僵尸恢复
    Given 单次执行尝试上限 10 分钟（取消令牌贯穿模型流式调用与流程引擎）
    When 模型渠道挂死或流程长时间无响应达到上限
    Then 本次尝试按失败处理并给出「执行超时」错误，按重试策略进入下一轮或终态失败，不再无限停留在执行中
    Given 宿主重启/进程挂死遗留的执行中（Running）记录（实际无人在跑）
    When 清理服务每 5 分钟扫描一次（启动即扫）
    Then 开始时间超过 30 分钟仍为执行中的记录被置为终态失败（错误信息注明自动恢复），不会永远显示执行中
```

```gherkin
Feature: 定时执行落会话（2026-10-30 起，推翻早期「不产生用户可见会话」决策）
  Agent 应用的每次定时执行创建独立会话（app_agent_session，UserType=timer），走与网页对话同口径的正式链路（发布快照 + token 记账 + 消息落库 + AI 提炼标题）。

  @TIMER-S14
  Scenario: 执行会话在应用日志页可见，本人会话列表排除
    Given 定时器绑定已发布 Agent 应用并执行一次
    Then 产生一条 UserType=timer 的会话，消息含本轮提问与完整回答（工具调用过程随会话落库）
    And 会话 token 消耗聚合回写（日志页可见）
    When 团队管理员打开应用管理「日志」页
    Then 会话列表出现该定时任务会话，可按用户类型「定时任务」筛选，点开可看完整消息详情
    When 定时器创建者打开应用对话页的本人会话列表
    Then 定时任务会话不出现（不污染个人会话列表）
    And 执行记录携带 sessionId 与会话关联（Agent 应用）
    But 定时执行不计入应用使用次数（app-usage 保持「用户主动使用」口径）；流程应用不落会话（保持实例模式）
```
