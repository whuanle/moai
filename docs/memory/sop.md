# 记忆模块 SOP

## 1. 日常操作

- **开启/调整应用记忆**：工作台 → 应用 → 「长期记忆」卡片（团队 Admin+），配置后需发布生效（正式会话按发布快照）；向量化模型/维度由系统设置统一决定（卡片内只读回显，不可自选），平台未开启长期记忆时应用开关禁用。
- **允许用户接入全局记忆（管理员）**：「长期记忆」卡片内开关（不受模型锁定约束，随时可改，改后需发布）；开启后用户可在对话设置自行接入，关闭时用户记忆仅在本应用内使用。
- **用户记忆偏好**：对话页右上角设置面板 → 「长期记忆」：开启 / 关闭 两态；管理员允许时另有「全局记忆（跨应用）」接入 / 仅本应用 两态开关；「管理记忆」进入独立管理页（分页查看、删除单条、清空本应用）。
- **记忆管理页（个人跨应用）**：侧边栏「记忆管理」——「应用记忆」页签按应用查看本人记忆，可编辑单条/删除/清空本应用/存为全局；「全局记忆」页签维护个人跨应用记忆（新建/编辑/删除/清空），平台未开启时展示引导提示（root 引导至系统设置）。
- **开启长期记忆（root，总开关）**：系统设置 → 「长期记忆」卡片：选择公开启用中的 embedding 模型与维度（1~2000）→ 开启保存（先保存模型与维度再开开关）；模型/维度为**应用记忆与全局记忆统一口径**。统一模型已配置且平台已有任意记忆（应用或全局）后锁定，更换前需「清空全部记忆」（危险区按钮，Popconfirm 二次确认，清空所有应用记忆+全局记忆）。
- **清空应用全部记忆**：工作台「长期记忆」卡片底部危险区（Admin+，Popconfirm 二次确认），删除应用内所有用户的记忆；如需换平台统一模型，用系统设置的「清空全部记忆」一键清空全平台。

## 2. 存量库变更（必读）

EnsureCreated 只对空库生效，存量库按顺序手动执行（幂等）：

```bash
psql ... -f asserts/app_user_config.sql     # 补 memory_mode / memory_global_mode 列
psql ... -f asserts/app_memory_shard.sql    # 建分片登记表
psql ... -f asserts/setting.sql             # 补种 MEMORY_ENABLED/MEMORY_EMBEDDING_MODEL/MEMORY_EMBEDDING_DIMENSIONS（并清理旧 MEMORY_GLOBAL_* 键）
```

缺列的典型报错：`column a.memory_mode does not exist` / `column a.memory_global_mode does not exist`（userconfig 接口 500）。向量表 `__agent_mem_{appId}` 与全局表 `__agent_mem_global` 由首次写入自动创建，无需手动建。**旧版升级注意（2026-10-30 统一口径）**：历史应用记忆按各应用旧模型/维度写入，升级后运行时按平台统一模型解析，维度不一致的应用记忆会报错——由管理员「清空应用全部记忆」后按新口径重建；平台首次选择统一模型不受存量分片锁定。

## 3. 排障表

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 工具保存/自动提取未落库，日志出现「记忆向量化模型不可用」 | 平台统一模型被停用/渠道不可用/团队未授权 | 检查模型与渠道启用状态、团队授权；更换模型需先清空全部记忆 |
| 自动提取始终不落地 | 平台总开关未开、应用未开启 autoExtract、用户模式为关闭、RabbitMQ 不可用、外部会话/调试会话 | 按顺序核对；MQ 断连期间仅丢失当轮提取 |
| 应用保存记忆配置 400「平台未开启长期记忆，请先在系统设置中开启」 | `MEMORY_ENABLED` 未开启或未选统一模型 | root 在系统设置「长期记忆」卡片先选模型再开总开关 [@MEM-S1](./bdd.md#mem-s1) |
| 新建全局记忆 400「平台未开启长期记忆」 | `MEMORY_ENABLED` 未开启 | 同上；总开关同时管控应用记忆与全局记忆 |
| 「平台已有记忆，向量化模型与维度不可更换」 | 统一模型锁定（应用或全局任一记忆存在，防维度混表） | root 先「清空全部记忆」（系统设置，一键清空应用+全局）再改模型/维度 [@MEM-S31](./bdd.md#mem-s31) |
| 新建/检索记忆 400「向量化模型不可用」 | 统一模型被停用、渠道关闭或未设为公开 | 恢复模型启用/公开，或清空全部记忆后更换 |
| 对话无记忆注入 | 平台总开关未开、用户已关闭、应用未开启、无相关记忆（低于 minScore）、子代理上下文（设计上不注入） | 属预期行为；全局注入同样要求应用开启记忆且用户未关闭 |
| 全局记忆未在对话中生效 | 按 三级开关 顺序核对：平台 `MEMORY_ENABLED` → 应用 `allowGlobalMemory`（需重新发布）→ 用户「接入全局」开关；或相似度低于应用 minScore | 逐级核对开关；降低应用记忆 minScore 或确认全局内容相关 |
| AI 全局保存被拒「当前应用未开放全局记忆接入」 | 应用未允许 allowGlobalMemory 或用户关闭了接入（设计如此，模型会转告改用应用内记忆） | 属预期行为；如需全局保存由管理员开启允许接入 |
| 旧版升级后应用记忆报错（维度不一致） | 历史应用记忆按旧的应用级模型/维度写入，统一口径后运行时按平台模型解析 | 管理员「清空应用全部记忆」后按新口径重建（直切策略，见 [sdd.md](./sdd.md) D-M10） |

## 4. 验收流程

1. 启动后端（5210 或 5000），执行 `node local-dev/agent-memory-e2e.mjs [baseUrl]`，应 36/36 PASS（场景映射见 [tdd.md](./tdd.md)）。
2. 执行 `node local-dev/memory-management-e2e.mjs [baseUrl]`，应 54/54 PASS（记忆管理/全局记忆/统一设置门禁/三级开关/记忆工具，收尾自清理可重复跑；中断残留先跑 `node local-dev/memory-global-reset.mjs [baseUrl]` 复位）。
3. 日常抽查：root 在系统设置「长期记忆」卡片选择统一模型并开启总开关；管理员在应用「长期记忆」卡片开启记忆与允许接入（模型只读回显）；用户在对话设置开启接入并确认另一应用对话注入（回复引用「全局」标记内容）；侧边栏「记忆管理」核对应用列表计数与全局记忆 CRUD。
