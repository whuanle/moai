# 记忆模块 SOP

## 1. 日常操作

- **开启/调整应用记忆**：工作台 → 应用 → 「长期记忆」分区（团队 Admin+），配置后需发布生效（正式会话按发布快照）；「管理记忆」按钮进入当前登录用户的本应用记忆管理页。
- **用户记忆偏好**：对话页右上角设置面板 → 「长期记忆」：开启 / 关闭 两态（无跨应用，记忆仅应用内使用）；「管理记忆」进入独立管理页（分页查看、删除单条、清空本应用，不可编辑）。
- **清空应用全部记忆**：工作台「长期记忆」分区底部危险区（Admin+，Popconfirm 二次确认），删除应用内所有用户的记忆。

## 2. 存量库变更（必读）

EnsureCreated 只对空库生效，存量库按顺序手动执行（幂等）：

```bash
psql ... -f asserts/app_user_config.sql     # 补 memory_mode 列
psql ... -f asserts/app_memory_shard.sql    # 建分片登记表
psql ... -f asserts/setting.sql             # 补 AGENT_COMPACTION_DEFAULTS 设置种子
```

缺列的典型报错：`column a.memory_mode does not exist`（userconfig 接口 500）。向量表 `__agent_mem_{appId}` 由首次写入自动创建，无需手动建。

## 3. 排障表

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 工具保存/自动提取未落库，日志出现「记忆向量化模型不可用」 | 应用配置的 embedding 模型被停用/渠道不可用/团队未授权 | 检查模型与渠道启用状态、团队授权；更换后需保证维度一致 |
| 自动提取始终不落地 | 应用未开启 autoExtract、用户模式为关闭、RabbitMQ 不可用、外部会话/调试会话 | 按顺序核对；MQ 断连期间仅丢失当轮提取 |
| 「应用内已有用户记忆，请先清空应用记忆再更换向量化模型或维度」 | 维度变更守卫（防维度混表） | 先执行「清空应用全部记忆」再改模型/维度 |
| 对话无记忆注入 | 用户已关闭、无相关记忆（低于 minScore）、子代理上下文（设计上不注入） | 属预期行为 |

## 4. 验收流程

1. 启动后端（5210），执行 `node local-dev/agent-memory-e2e.mjs`，应 25/25 PASS（场景映射见 [tdd.md](./tdd.md)）。
2. 日常抽查：管理员在「长期记忆」分区查看本人记忆样例；对话页设置面板核对模式切换与清空按钮。
